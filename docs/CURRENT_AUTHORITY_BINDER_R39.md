## Binder semantics

The binder validates repository, exact Git SHA, exact CI run/conclusion, artifact ID/digest, contract IDs, and Git blob lineage. Authority manifests contain no branch/ref authority. An external QA envelope is accepted only when it binds the exact Media R27 producer SHA, CI, artifact/digest, local contract and Growth-bundle contract.

The durable operation identity includes the exact authority-set digest, each authority-manifest digest and the sealed Media R27 bundle digest. Reusing the same workspace with changed authority or bundle bytes raises a replay conflict.

R39 reuses the immutable R38 Media authority validator and R38 `StageLedger`. Its proof graph is verified by the existing R37 proof-graph verifier, and its release-escrow control evidence is generated by the existing R37 release-escrow fixture path. No provider/browser/social side effect is added.

## Commands

```text
creator-current-authority-r39 readiness
creator-current-authority-r39 fixture --workspace .r39-fixture
creator-current-authority-r39 evidence --out .r39-evidence
creator-current-authority-r39 status --workspace .r39-fixture
```

After independent QA exists, the coordinator may supply the exact QA envelope and sealed Media R27 Growth bundle:

```text
creator-current-authority-r39 bind --bundle <media-r27-growth-manifest.json> --media-qa <accepted-media-r27-qa.json> --workspace <local-workspace> --operation-id <stable-id>
```

Until then, `bind` fails closed. The deterministic fixture still terminates `LOCAL_REHEARSAL_COMPLETE / LIVE_AUTHORIZATION_FALSE`; this is control-plane evidence only and is not an actual local-PC E2E claim.

## Safety boundary

R39 performs no provider mutation, browser mutation, live Bridge cutover, credential use, social publish, or live authorization. Hosted CI uses only deterministic fixture bytes and authority metadata.
